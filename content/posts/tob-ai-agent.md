现在 Workbuddy、DeepSeek harness 这类的 C 端 Agent 产品比较火，在这类产品中现在都不约而同的有专家、技能、连接器这几个概念。

在 B 端谈及 AI 项目的时候，会提到 Agent（智能体）、AI 数字员工、AI 助手等，腾讯的 WMA 对 Agent 的定义是：

> Agent 是平台的核心对象，由角色设定（System Prompt）、模型、能力集（Skills / 连接器）与行为约束构成。支持 Agent 的创建、编辑、A2A 通信、发布与版本管理；产出的 Agent 支持多渠道接入、自动化任务、API 调用，也可推送到关联企业范围内使用。

如果只是以智能体为核心，赋予智能体一些能力，对外开放使用，还会存在一些问题：

1、当智能体越来越多，用户怎么选择成了一个难题；

2、授权后变得异常复杂，因为最小颗粒度是智能体，有交叉的地方又要新创建一个智能体。

所以，我认为对于 B 端 Agent 平台来说：

1、给我一堆专家、AI 员工，不如就一个对话框，用户具备什么权限的能力，让用户自己选，不选也行，根据用户的意图系统来选；

2、技能、连接器（目前主要是 MCP 服务）、模型、规则这些应该都是可以供权限设置的资源对象，除此之外在 B 端还应该有知识库和数据库；

3、C 端产品都有专家这个概念，我理解就是上面一些资源的封装，让用户可以更方便使用而已，所以专家也好、专家团也好，依然是被授权的一个对象；

4、用户的入口可以多样化，可以是企业微信、钉钉，也可以是第三方系统中内嵌的一个网页、还可以直接在 workbuddy 等工具中使用，利用这些工具的 harness 这一层的能力，所以平台中要具备分发的能力，能将各种资源、能力发布给外部使用。

5、至于说用户的记忆、怎么循环去完成一个目标，这些是锦上添花的事情。

AI 的发展速度很快，目前连接器主要是 MCP ，再过几个月，可能就会有新的东西，资源的种类和方式也会越来越丰富。

最近 Coze 企业版下线了，因为靠低代码拖拽来弥补大模型能力不足的过渡性产品形态，正在被模型自身能力的进化所吞没。

但在我上面说的架构中就不存在问题，在我看来，Coze 这类的拖拽出来的工作流也是资源的一种，不流行了，就去掉，后面有更好的、更新的出来，就加到资源中。

针对上面的想法，用 AI 简单做了点示例。

## 资源中心

资源分为文档、数据、技能、连接器、模型、规则

### 知识库

非机构化的数据在这里进行维护。

![](https://img.fwhyy.com/2026/20261109211348.webp)

上传的文档会自动进行向量化，也可以仅上传，都上传完后再统一进行向量化解析。

![](https://img.fwhyy.com/2026/20261109212131.webp)

不同的文档会有不同的解析方式，可以批量设置，也可以单个文档设置。

![](https://img.fwhyy.com/2026/20261109212320.webp)

文档向量化后可以通过问答测试的方式来调整参数

![](https://img.fwhyy.com/2026/20261109213216.webp)

### 数据

主流的关系型数据库和国产数据库都是需要支持的。

![](https://img.fwhyy.com/2026/20261109213346.webp)
![](https://img.fwhyy.com/2026/20261109213807.webp)

这里的数据源类型出来普通类型，还有一个低代码平台的类型，这个低代码平台指的就是我们自己的 S2 ，选择这个类型，可以将低代码平台中的数据模型的关系、编码等都同步过来，可以做更多和低代码平台之间交互的功能。

![](https://img.fwhyy.com/2026/20261109213324.webp)

数据主要用与问数的场景，除了表和字段之外，还可以设置指标、业务规则、SQL 样例等。

![](https://img.fwhyy.com/2026/20261109214744.webp)

### 技能

技能就是现在流行的 SKILL，只不过系统内置了一些默认的技能，也可以管理员进行维护。

![](https://img.fwhyy.com/2026/20261109215042.webp)

除了系统内置，还可以自定义上传，技能的 Markdown 文件内容也可以在线编辑。

![](https://img.fwhyy.com/2026/20261109215203.webp)

### 连接器

连接器主要是将外部系统提供的 MCP 服务注册到系统中，比如低代码平台提供了应用构建的相关 MCP 服务，可以注册到系统，通过对话的方式来创建应用和功能。

![](https://img.fwhyy.com/2026/20261109215336.webp)

注册连接成功后，可以看到 MCP 服务的所有工具列表。

![](https://img.fwhyy.com/2026/20261110072404.webp)

### 模型

系统中可以支持多种模型的配置，模型一样是作为资源，通过权限配置的方式提供给用户。

![](https://img.fwhyy.com/2026/20261108170235.webp)

### 专家管理

专家这个概念在 workbuddy 中就有，我理解为一层封装，将资源中心的中的一个或多个组合起来，再配合提示词形成一个可以处理复杂业务的能力

![](https://img.fwhyy.com/2026/20261110072939.webp)

在专家的编辑界面，可以配置专家的类型、角色提示词，选择相关的资源等。

![](https://img.fwhyy.com/2026/20261110073119.webp)

专家团则是对多个专家进行一定程度的编排，完成更复杂的需求。

![](https://img.fwhyy.com/2026/20261110073443.webp)

封装后的专家或者专家团也会作为授权的一个对象，和资源中心的资源一起被授权。

## 权限管理

资源中心的每种资源和专家都可以按照角色的方式进行授权。

![](https://img.fwhyy.com/2026/20261110074117.webp)

用户在对话界面就可以任意使用被配置权限的资源

![](https://img.fwhyy.com/2026/20261110074441.webp)

## 对外发布

如果客户不使用 Agent 平台作为入口，也没有关系，Agent 平台中沉淀的业务知识、技能等，可以封装成 MCP 服务对外发布。

![](https://img.fwhyy.com/2026/20261110074651.webp)

除了 MCP 之外，还可以支持企业微信、钉钉、飞书作为入口，也可以在第三方系统中内嵌网页的形式使用，还可以在外部使用 API 调用的方式接入。

![](https://img.fwhyy.com/2026/20261110074943.webp)

## 一个小示例

1、S2 上的开放 MCP 服务中有 s2_design_app_create 的工具 。

![](https://img.fwhyy.com/2026/20261110075251.webp)

2、将这个 MCP 服务注册到资源中心的连接器中。

![](https://img.fwhyy.com/2026/20261110075442.webp)

3、通过分发管理的 MCP 服务，对外发布这个连接器。

![](https://img.fwhyy.com/2026/20261110080016.webp)

4、在 workbuddy 中的连接其中进行配置。

![](https://img.fwhyy.com/2026/20261110080151.webp)

5、配置成功后，需要信任并开启，就能找到 MCP 里的工具了。

![](https://img.fwhyy.com/2026/20261110080258.webp)

6、在 workbuddy 中通过对话的方式进行应用的创建。

![](https://img.fwhyy.com/2026/20261110080422.webp)

7、S2 的应用管理中就会多一个应用了。

![](https://img.fwhyy.com/2026/20261110080615.webp)
